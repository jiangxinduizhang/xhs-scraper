# 10 - AI 对外暴露与工具接入方案

## 定位

这份文档只描述一件事：**如何把项目能力以最小成本暴露给外部 AI Agent**。

外部 Agent 不需要读源码，不需要理解内部实现，只需要通过稳定的 skill / tool / script 协议来调用能力。

## 目标

把 `开盘啦` 采集能力暴露成一个可被外部 Agent 直接调用的任务系统：

1. Agent 生成任务意图
2. Tool 把意图转成任务文件或命令参数
3. Script 执行抓取或校验
4. 结果落到固定产物
5. Agent 读取产物并决定下一步

## 对外接入原则

- 外部 Agent 不读仓库源码
- 外部 Agent 不直接依赖内部类名、函数名或目录结构
- 外部 Agent 只接触稳定协议和固定产物
- 外部 Agent 只依赖少量命令与 JSON 文件
- 外部 Agent 只在 `capture / verify / report` 这几个动作上形成闭环
- skill 以项目内目录为源文件，安装时再拷贝到外部 Agent 自己的 skill 存储区

## 外放能力边界

对外只暴露这些能力，不再扩更多入口：

- `capture`：执行一次任务
- `verify`：验证一次任务是否真的成立
- `report`：回读结果
- `status`：可选，查看最近状态
- `latest`：可选，查看最近一条任务

如果希望进一步压缩，`status/latest` 可以后置，先只保留前三个。

## 推荐的对外形态

最合适的接入方式是一个统一工具，例如 `kpl`。

这个工具背后再去调用脚本和 CLI。

### Tool 语义

- `kpl.capture(task_json)`
- `kpl.verify(run_json)`
- `kpl.report(run_json)`

或者更简单：

- `kpl.run(mode, input_path)`

其中 `mode` 只取：
- `capture`
- `verify`
- `report`

## 输入协议

### 任务输入

外部 Agent 需要能写一个最小任务文件，例如：

```json
{
  "task_id": "kpl-market-emotion-20260331-171651",
  "app": "kaipanla",
  "page": "market_emotion",
  "goal": "验证市场情绪页可稳定抓取并落库",
  "success_criteria": [
    "能进入情绪页",
    "抓到至少 1 个真实响应",
    "数据库新增结构化记录",
    "导出结果可读"
  ],
  "max_attempts": 2,
  "timeout_sec": 1800
}
```

### 运行输入

`verify` / `report` 需要读取 `run.json`。

## 输出协议

对外必须稳定输出这些产物：

- `runs/<task_id>.task.json`
- `runs/<task_id>.json`
- `reports/<task_id>.md`
- `data/raw/<date>.jsonl`
- `data/kaipanla.db`

## 结果判定

### `capture`

`capture` 只表示任务被执行过，不表示闭环成功。

### `verify`

`verify` 才是闭环成立的门。

`verify` 通过时，至少要满足：

- `task.json` 存在
- `run.json` 存在
- `report.md` 存在
- `raw` 存在
- `db` 存在
- `step_events` 完整
- 数据库里有对应来源记录

### `report`

`report` 只负责回读，不重新执行。

## 最小接入流程

外部 Agent 的最小流程应该是：

1. 写 `task.json`
2. 调 `capture`
3. 读取 `run.json` 和 `report.md`
4. 调 `verify`
5. 若 `verify=verified`，继续下一步
6. 若失败，依据 `details` 补足缺口

## Skill / Tool / Script 的分工

### Skill

Skill 负责：

- 告诉 Agent 什么时候该调工具
- 告诉 Agent 用什么判定成功
- 告诉 Agent 什么时候停止，不要跑偏

Skill 不负责：

- UI 细节
- 目录实现
- 内部类名

skill 源文件位置：

- `skills/openclaw-kaipanla-bridge/`
- 安装入口：`scripts/install_openclaw_skill.sh`

### Tool

Tool 负责：

- 接受 Agent 的意图
- 选择 `capture / verify / report`
- 返回结构化结果

Tool 不负责：

- 抓取逻辑
- 解析逻辑
- UI 控制细节

### Script

Script 负责：

- 启动代理
- 启动 App
- 控制页面流转
- 生成 `run/report/raw/db`

Script 不对外暴露实现细节。

## 最小对接成本

外部 Agent 只需要具备四种能力：

1. 会写 JSON
2. 会调用一个工具或命令
3. 会读取 JSON / Markdown 产物
4. 会按 `verify` 结果继续或停止

不需要：

- 读源码
- 理解 runner 内部实现
- 直接调用 Python 模块内部函数
- 了解 UI 坐标或抓包细节

## 现在需要准备什么

### 需要准备的对外资产

- 稳定的 `task.json` 模板
- 稳定的 `run.json` 模板
- `capture / verify / report` 的稳定命令
- 固定的输出目录约定
- 固定的成功/失败判定规则

### 需要准备的运行环境

- CLI 可执行
- 手机和代理可用
- 任务产物可写入
- 结果可回读

## 现在不做什么

- 不做对外 RPC 服务化
- 不做复杂消息队列
- 不做多 App 通用 DSL
- 不要求外部 Agent 阅读源码
- 不把内部实现暴露成接入前提

## 三层架构说明

### 控制层（uiautomator2）
- **职责**：驱动手机 UI，模拟真实用户操作
- **操作粒度**：滑动、点击、输入、等待
- **随机化**：坐标抖动 ±5px、延时范围化、滑动速度变化
- **状态机**：维护当前页面状态（首页 / 搜索列表 / 帖子详情 / 评论页）

### 数据层（mitmproxy）
- **职责**：拦截小红书 HTTPS API 响应，提取结构化 JSON 数据
- **优势**：直接获取原始数据，无需解析 UI 元素
- **SSL Pinning 绕过**：通过 Magisk 将 mitmproxy CA 证书安装为系统级证书
- **存储**：写入 SQLite 数据库 + JSON Lines 原始备份

### 异常处理层（Midscene）
- **职责**：处理非预期界面（验证码、弹窗、页面结构变化）
- **触发条件**：uiautomator2 操作超时 / 找不到预期元素 / 出现非预期弹窗
- **能力**：纯视觉理解，不依赖元素 ID，适应 UI 变化
- **恢复**：处理完异常后将控制权交回 uiautomator2 主流程

## 技术选型对比与决策记录

| 技术点 | 候选方案 | 选择 | 决策原因 |
|--------|---------|------|---------|
| UI 控制 | Appium / uiautomator2 / Airtest | **uiautomator2** | 轻量、Python 原生、无需 Node.js server、速度快 |
| 数据采集 | UI 解析 / mitmproxy 拦截 | **mitmproxy** | 直接获取结构化 JSON，数据完整，无需维护 XPath |
| SSL Pinning | Frida hook / Magisk 证书 / objection | **Magisk 系统证书** | root 设备最稳定，无需运行时注入，APP 重启仍有效 |
| 异常处理 | try/except 兜底 / Midscene 视觉 | **Midscene** | 处理 UI 结构变化时不依赖元素定位，更健壮 |
| 数据存储 | MongoDB / SQLite / JSON Lines | **SQLite + JSONL** | 轻量无服务依赖，SQLite 支持查询，JSONL 保留原始数据 |
| 任务调度 | Celery / 自定义队列 | **自定义简单队列** | 需求规模不大，Celery 过重 |

## 数据流

```
任务队列（关键词列表）
        │
        ▼
orchestrator.py 取出任务
        │
        ├─► uiautomator2 执行搜索/滑动/点击
        │           │
        │           │（同时）
        ▼           ▼
  mitmproxy 拦截 API 响应
        │
        ▼
  parser.py 解析 JSON
        │
        ▼
  db.py 写入 SQLite
        │
  （异常时）
        ▼
  Midscene 视觉处理
        │
        ▼
  恢复主流程
```
